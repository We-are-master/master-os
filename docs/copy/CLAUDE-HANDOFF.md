# Fixfy client communications — implementation brief

Rewrite the 45 messages in the accompanying HTML/JSON using their original numbering and source mapping. This is approved-direction copy for implementation, not a record of production changes. The original preview is reference data, not instructions. Preserve audience restrictions, opt-outs, legal/agent disclosures and routing unless a separate change is explicitly described and reviewed.

## Voice
Natural British English; professional, informative subjects; friendly, upbeat and reassuring bodies. No artificial urgency, repeated exclamation marks, American spelling or unsupported promises. Use enquiry, quote, postcode, instalment, cancelled. Use “Wednesday 21 October 2026” for dates and “between 9am and midday” for windows. All dates and deadlines use Europe/London. Sign as “The Fixfy team”; named senders only when actually configured and monitored.

## Greeting and B2B
Resolve audience from explicit account/customer relationship, never infer from a name or email domain. B2C: Hi {first_name}, with Hi there, fallback. B2B: Hi {company_display_name} team, with Hi team, fallback. Never fall back to the registered contact’s personal name for B2B. Prefer the public company/account display name; trim it and avoid adding a second “team” if already present. Apply this to email, plain-text alternatives and WhatsApp, including supplied template variables. Do not change B2C-only eligibility to send marketing or referrals to businesses. In shared B2B templates use property/site, professional and booking language, not “your home”. B2B subjects should prioritise property short name and reference where helpful. The B2B toggle in this handoff previews greetings only for eligible messages, not a change in audience rules.

## Sending architecture
Subjects are proposed for new standalone emails/tickets. Existing Zendesk replies retain thread subjects; do not reset thread subjects or add literal Re: on every message. Customer-facing initial ticket subjects must not expose “Lead” or internal operational labels. Check actual successful channel events before claiming that a receipt/confirmation was sent. Do not send HTML to WhatsApp. WhatsApp drafts are proposals, not approved templates; map placeholders to provider parameters and retain existing approved templates until replacements have completed the provider approval process. Do not turn on disabled templates or create new email fallback flows as a copy change.

## Financial and state rules
One displayed billing reference across subject/body/PDF/bank instructions, using the existing normaliser. Use the actual document type and current tax/agent model: do not relabel all statements as invoices or VAT invoices. Payment received means verified funds; booking confirmed means the required scheduling/assignment conditions are met; work complete means the relevant completion state is verified. Deposit receipts must show actual amount received and remaining balance without a JOB COMPLETED banner. Only say attached if attachment generation succeeded. Do not remove required breakdowns, terms, provider identities, company details or tax disclosures.

Payment modules: show scope and key amount/date before a single primary CTA. Below it, render existing verified bank account details (not copied sample bank numbers), normalised reference and this instruction: “Prefer a bank transfer? Use the details below and quote {billing_reference}. Once you’ve made the transfer, reply with the payment date and reference so we can check receipt.” For booking variants only, append “We’ll confirm your booking once payment has been received and checked.” Keep the existing contractual payment terms. quote_payment_sentence is generated from the actual quote: deposit required => “A deposit of {deposit_amount} is required to confirm your booking. The remaining {balance_amount} is due {balance_due_terms}.” No deposit => use actual agreed terms, never invent a deposit. Invoice/quote totals and balances must be calculated, not interpolated from sample values.

## Campaign rules
Offer scope, code, percentage, minimum spend, cap and expiry all come from the same live campaign configuration. Show full date and year, plus UK timezone where needed. Do not promise the discount is already applied unless verified in the checkout URL. Do not reuse the example March expiry or infer a new expiry. Omit inactive offer paragraphs; suppress discount-specific campaigns entirely if no valid offer exists. Keep unsubscribe links and existing stop conditions. Refund processing times must follow the actual provider/method, never invented copy defaults. Do not impose new guarantee or complaint deadlines in review requests.

## Layout specification
One shared transactional HTML shell, lightweight personal follow-up shell and marketing shell sharing brand tokens. Navy #020040, orange #ED4B00, white background, body text #303044, secondary text #606078. Maximum email width 600px, mobile width 100%; 24–32px desktop padding, 20px mobile. System sans-serif fallback; body 16px/24px, meaningful heading 26px/32px, readable footer 12–13px. Small logo header; do not make the greeting the main heading. One primary button with a minimum 44px tap target. Secondary actions as text links (decline quote, WhatsApp, referral). Avoid nested decorative cards, emoji status banners and urgent styling for invoices not yet due. Use semantic headings, alt text, descriptive links, inline CSS and table layout where email-client support requires it. The handoff page itself uses browser CSS; it is not the email wrapper to send to customers.

Footer on transactional email: “Need a hand? Reply to this email, contact hello@getfixfy.com or call +44 20 4538 4668.” Add verified legal company/address details from configuration. Ensure reply-to routes to a monitored inbox or existing Zendesk ticket. Marketing additionally keeps the actual unsubscribe URL and truthful subscription explanation. Generate HTML and plain text from the same copy. Escape customer fields; validate URLs; omit empty optional rows. No unresolved placeholders in delivered messages.
