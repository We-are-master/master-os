As três perguntas

A API oficial está no Zendesk. Dá para ter no OS também?Não precisa: o OS já usa o mesmo número pelo Zendesk

O número 020 4538 4668 mora numa WABA só, e o Zendesk é quem recebe as respostas. Desde 08/10 o OS manda os templates por esse mesmo número, pela API do Zendesk (Sunshine), porque a Cloud API direta perdeu a permissão. Assim tudo cai na mesma conversa. Ligar a Cloud API direta de novo no OS é possível, mas a conversa ficaria dividida em dois lugares.

O CRM conecta 100% com o status do Zendesk?A etapa sim, numa direção: OS → Zendesk

Cada etapa vira um status que o Zendesk já tem (Lead, Needs Quote, Bidding, Awaiting Approval, Awaiting deposit, os status do job). Só falta criar um: Nurture. Do Zendesk para o OS vêm só sinais (cliente respondeu, ticket novo). Mudança manual no ticket é desfeita pelo espelho, como já acontece com os jobs.

O CRM tem tudo para criar o job no Won?Hoje não. Faltam 6 grupos de dados

O lead já guarda cliente, endereço, serviço do catálogo, scope e fotos. Faltam data e janela de chegada, tipo do job, preço do cliente, custo do parceiro, entrada paga e o ticket. O desenho põe esses campos no lead e um checklist "Ready for job": o botão Won só acende com tudo verde.

Zendesk

Etapa do CRM → status do ticket

O status conta a etapa. Quem precisa responder fica no campo Reply Status, não no status: quando o cliente responde, o Zendesk abre o ticket sozinho, o OS marca a resposta e o espelho devolve o status certo na próxima passada (10 min).

Processo 1

Pedido B2C do site até o job

Cada caixa é um passo, cada raia é quem faz. A cor é a etapa do lead naquele momento.

Processo 2

Pedido de uma conta B2B

Mesmas etapas, outra régua: só e-mail, preço da conta, entrada conforme os termos.

Processo 3

Quote sob medida com lance de parceiro

O que acontece dentro de Quoting até o pagamento.

Processo 4

Silêncio, Nurture e volta

Nenhum lead fica parado: ou alguém age, ou a régua age, ou ele dorme com data para voltar.
